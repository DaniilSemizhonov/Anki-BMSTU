# Anki Web — локальная веб-версия

Браузерный интерфейс для настоящей коллекции Anki: колоды, карточки и повторение.
По умолчанию сервер работает на этом компьютере; данные сохраняются между запусками.
Для сервера подготовлен стек из отдельных backend и web контейнеров: [инструкция](../DEPLOYMENT.md).

## Запуск на macOS / Linux

Нужен Python 3.10 или новее. Из корня репозитория:

```sh
sh web/run.sh
```

Откройте **http://127.0.0.1:8765**. Для остановки нажмите Ctrl+C в терминале.
При первом запуске скрипт создаёт `web/.venv` и устанавливает библиотеку Anki из PyPI.
Следующие запуски используют готовое окружение.

Другой порт:

```sh
sh web/run.sh --port 8766
```

На Windows создайте окружение и запустите сервер вручную:

```powershell
py -3 -m venv web/.venv
web/.venv/Scripts/python -m pip install -r web/requirements.txt
web/.venv/Scripts/python web/server.py
```

Windows-запуск пока не проверен.

## Возможности

- Создание колод, включая вложенные: `Языки::Английский`.
- Обычные, обратные и cloze-карточки; редактирование меток, HTML и загрузка медиа до 10 МБ.
- Дневные лимиты и переименование колод; приостановка, возобновление и откладывание карточек.
- Отмена последнего действия и ответа; статистика за 30 дней; мобильный интерфейс и тёмная тема.
- Повторение через планировщик Anki с четырьмя оценками и реальными интервалами.
- Отображение доступной очереди, общего количества карточек и ответов за день Anki.
- Поиск по коллекции с синтаксисом Anki и фильтром по колоде.
- Редактирование полей заметок, включая импортированные типы. Поля редактируются как HTML.
- Импорт `.apkg` до 100 МБ и экспорт всей коллекции с медиа и расписанием.
- Раздел «Настройки» (⚙): импорт `.md` с предварительным просмотром, экспорт Markdown в ZIP и ручной обмен с Fast Note Sync.
- Показ HTML/CSS карточек, локальных изображений, звуков и видео через элементы браузера.
- Пробел открывает ответ, клавиши 1–4 выбирают оценку. Также доступны экранные кнопки.

Новые карточки используют стандартные типы `Anki Web Basic`, `Anki Web Reversed`
и `Anki Web Cloze`. Пропуски записываются как `{{c1::ответ}}`; разные номера
создают отдельные карточки. Дневные лимиты применяются к конкретной колоде.
Поиск показывает до 200 заметок; заметка может создавать несколько карточек.
Размер очереди учитывает лимиты и интервалы Anki. Вложенные колоды входят в счётчик родительской.

## Где данные

### Markdown и Fast Note Sync

Откройте ⚙ в верхней панели. В настройках есть адрес сервиса, название хранилища
(vault), папка и токен доступа. Сначала сохраните подключение и проверьте его.
Нужен токен Fast Note Sync с REST-доступом к чтению и записи заметок в выбранном
хранилище; идентификатор клиента Anki — `anki-web`. Пустое поле токена сохраняет
прежнее значение; для удаления токена предусмотрен отдельный флажок.

«Выгрузить в хранилище» записывает по одному `.md` на заметку в указанную папку.
Файлы имеют стабильные имена и свойство `anki_guid`, поэтому повторная выгрузка
обновляет их. Это ручная выгрузка текущей версии из Anki: если редактировали
Markdown в хранилище, сначала импортируйте его в Anki, чтобы не заменить правки
старой версией. Удаления файлов или карточек на другую сторону не переносятся.

«Прочитать из хранилища» и «Выбрать .md с компьютера» сначала показывают количество
добавляемых, обновляемых и неизменившихся заметок. Изменения применяются только
кнопкой «Применить импорт». Их можно отменить одной кнопкой ↶. Ошибка в одном
файле отменяет весь импорт. До 500 файлов и 10 МБ за один раз; сетевой обмен
ограничен минутой (после частичной выгрузки её можно повторить).

В простом файле одна заметка:

```markdown
---
anki_kind: basic
tags: [география]
---

## Вопрос

Столица Франции?

## Ответ

**Париж**.
```

Также поддерживается `# Вопрос` с ответом ниже и cloze `{{c1::текст}}`.
`anki_kind` принимает `basic`, `reversed` или `cloze`; `anki_deck` задаёт колоду
для новой заметки. Без него используется выбранная в настройках колода.
У файла без `anki_guid` связь определяется его именем и выбранной колодой:
повторный импорт этого имени обновляет заметку. Переименование такого файла
создаст другую заметку. В экспортированных файлах не удаляйте `anki_guid`,
остальные свойства и комментарии-разделители полей.

У существующих заметок обновляются поля и метки; колоды, типы, расписание и история
сохраняются. Пользовательские типы можно переносить только в коллекцию, где уже
есть соответствующий тип с теми же полями (перенесите его через `.apkg`).
Markdown переносит содержимое, а не шаблоны или оформление типов. HTML может
нормализоваться при преобразовании; это не замена резервной копии `.apkg`.
Изображения и аудио не копируются: остаются ссылки на файлы коллекции Anki.

Настройки лежат в `markdown-settings.json` рядом с коллекцией, токен не возвращается
через API. Файл создаётся с правами `0600`. Защитите резервные копии этого файла
так же, как пароль. Браузер обращается только к Anki, а Anki — к Fast Note Sync.
Про развёртывание на своём сервере см. [DEPLOYMENT.md](../DEPLOYMENT.md#fast-note-sync-и-markdown).

По умолчанию используется `web/data/collection.anki2`, медиа находятся рядом в
`web/data/collection.media`. Эта папка и виртуальное окружение исключены из Git.
Настольная коллекция автоматически не открывается и не меняется.

Для переноса из настольного Anki экспортируйте колоды в `.apkg` и нажмите
«Импорт .apkg». Существующие заметки могут обновляться по правилам импорта Anki.
Чтобы перенести изменения обратно, используйте «Экспорт коллекции».

Для другой **отдельной** коллекции:

```sh
sh web/run.sh --collection /absolute/path/collection.anki2
```

Одну коллекцию должен открывать только один процесс. Для резервной копии остановите
сервер и скопируйте всю папку данных либо экспортируйте коллекцию через интерфейс.

## Устройство

`server.py` использует официальный Python-пакет `anki==26.9.3`, в котором уже собран
Rust backend. Именно Anki хранит данные и рассчитывает расписание. HTTP API и
браузерный интерфейс добавлены в `web/`; Qt для запуска не нужен.

Пакет из PyPI позволяет запустить веб-интерфейс без полной сборки настольного Anki.
Изменения Rust/Python-кода в остальных папках этого checkout не подхватываются
автоматически. Чтобы использовать их, нужно собрать библиотеку из исходников
по инструкции репозитория и установить полученный wheel в `web/.venv`;
после этого запускайте `web/.venv/bin/python web/server.py` напрямую, поскольку
`run.sh` устанавливает указанную выше опубликованную версию.

Сервер однопроцессный, по умолчанию привязан к `127.0.0.1` и предназначен для одного пользователя
на этом компьютере. Активное повторение общее для вкладок: новая сессия или
изменение коллекции делает ранее выданную карточку недействительной. Повторная
отправка одной оценки отклоняется сервером.

Для защищённого доступа предусмотрены `ANKI_PUBLIC_URL` (внешний HTTPS-origin),
`ANKI_WEB_PASSWORD` (пароль от 12 символов) и необязательная пара
`ANKI_TELEGRAM_BOT_TOKEN` / `ANKI_TELEGRAM_USER_ID`. Они читаются из окружения процесса;
`run.sh` сам `.env` не загружает. Docker Compose читает корневой `.env` автоматически.
Подробности — в [DEPLOYMENT.md](../DEPLOYMENT.md).

Пароль и разрешённый Telegram-аккаунт открывают одну личную коллекцию. Сессии
хранятся в памяти 24 часа и исчезают при перезапуске. Telegram-вход проверяет HMAC,
свежесть `initData` и ID владельца. Клиент загружает официальный SDK только при
включённой Telegram-интеграции. Проверка с настоящим Telegram-ботом пока не выполнена.

Для разделённого запуска backend использует `--api-only --host 0.0.0.0`. В таком
режиме статику обслуживает web-контейнер. Внешний интерфейс backend требует
авторизации и HTTPS-origin; локальный режим остаётся доступен без переменных.

Ещё предстоят редактор типов заметок и шаблонов, настройка/оптимизация FSRS,
фильтрованные колоды, офлайн-режим, синхронизация, Image Occlusion и дополнения.
Интерфейс показывает используемый алгоритм, но не изменяет параметры FSRS.
JavaScript карточек отключён; интерактивные шаблоны, ввод ответа, MathJax и TTS
требуют отдельной доработки. Рендер Anki помещается в iframe без разрешения скриптов.
Удалённые изображения и внешние ресурсы карточек блокируются. Воспроизведение
медиа зависит от поддерживаемых браузером кодеков. Загруженные, но не использованные
вложения пока автоматически не удаляются.

## Проверки

```sh
web/.venv/bin/python -m unittest discover -s web -p 'test_*.py' -v
node --check web/static/app.js
sh -n web/run.sh
```

При наличии `just` используйте `just check-web`. Общий `just check` в этой среде
не выполнен: `just` не установлен.

Интеграционные тесты используют временные настоящие коллекции и отдельный локальный
HTTP-сервер: создание, поиск, редактирование, повторение, сохранение, защита от
повторной оценки, перенос `.apkg` с историей и медиа, обработка некорректных запросов.
Они не затрагивают `web/data`.

Визуальная проверка в браузере в этой среде не выполнена: доступ к браузеру отключён.
